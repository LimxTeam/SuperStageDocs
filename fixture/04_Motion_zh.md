# 灯具运动控制

> 适用版本：SuperStage 26H2.6 起 ｜ 前置阅读：[灯具定义资产](01_FixtureDefinition_zh.md)

本文说明数据驱动灯具怎么动：Pan / Tilt 行程从哪来、速度通道怎么解释、无极旋转按什么转、多头灯怎么各转各的。

一支灯能不能动，取决于两件事：**钻机里这根轴存在且启用**，以及**绑定把某条通道接到了这根轴的能力上**。缺任何一样，控台推得动而灯不动。

---

## 1. 轴

灯具定义的钻机最多三根轴：

| 轴 | 通常是 | 对应能力 |
| --- | --- | --- |
| Axis A | 灯臂 / 摇摆 | Axis A Position (Pan) |
| Axis B | 灯头 / 俯仰 | Axis B Position (Tilt) |
| Axis C | 灯头自转 | Axis C Position (Spin) |

每根轴的运动相关字段：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| **Enabled** | — | 这根轴是否存在。关掉这根轴就完全不动 |
| **Rotation Axis** | — | 绕哪个本地轴转 |
| **Pivot Offset (cm)** | — | 转轴相对上一级的偏移。它决定灯头绕哪个点转 |
| **Range (deg)** | (−270, 270) | 机械行程 |
| **Invert** | 关 | 反向 |
| **Max Speed (deg/s)** | 0 | 转到目标角的最大角速度 |

### Range

**从 GDTF 包内声明导入。** 包里没写时按轴的角色兜底：摇摆 ±270°、俯仰 ±135°。

> 26H2.6 之前这一项从来没有从 GDTF 导入过，导致绝大多数灯的俯仰行程不正确。如果某支灯的俯仰看起来行程不对，先看这里的 Range 是不是包里带来的真实值。

DMX 归一化值 0 到 1 在 Range 内插值，所以 Range 是 (−270, 270) 时，0.5 对应中间位置 0°。改成非对称范围后，中间位置也跟着变。

### Max Speed

它是"转到某个角度"的最大角速度。

| 取值 | 行为 |
| --- | --- |
| **0（默认）** | 不限速，直接到位 |
| **> 0** | 按这个角速度逼近目标角，逐帧推进 |

> 灯库没填限速时就是 0，行为与旧版一致。要让灯"看起来在转过去"而不是瞬移，给这根轴填一个真实的角速度。

## 2. PT 速度通道

绑定 **Axis Speed (PT Speed)** 之后，这条通道整体缩放三根主轴与全部头轴的移动速度。

| 通道值 | 效果 |
| --- | --- |
| 0 | 最快（满速） |
| 1 | 最慢 |

**最慢是满速的 8%。** 再慢就成了"推了速度杆灯就不动了"，现场会当成灯坏了。

**没有绑定这条通道时按满速处理**，与通道推到 0 的效果一致。

这条通道只在轴的 `Max Speed > 0` 时有意义——不限速的轴本来就瞬间到位，没有可缩放的速度。它也**不影响无极旋转**（§3.2）。

> 灯具只在有轴还没走到位时才逐帧推进，全部到位就停止——静止的灯不占每帧开销。

---

## 3. 无极旋转

绑定 **Axis A / B Infinite Rotation** 之后，这条通道让轴持续旋转而不是转到某个角度。

这类通道的惯例是**一条通道分几段**：前面一小段定位，后面正转、反转各一段。例如某支灯的 Pan Rotation 是 `000-003 定位 / 004-129 正转 / 130-255 反转`。

每一段的行为由通道库子属性的 **RotationMode** 决定：

| RotationMode | 行为 |
| --- | --- |
| **Off** | 交回普通 Pan / Tilt 位置控制 |
| **Position** | 定位段，见下 |
| **Infinite** | 按转速持续旋转 |

> **`Stop` 已在 26H2.6 移除**，语义并入 `Off`。原先 Stop 的意思是"停止旋转并冻结当前角度"，但推杆停在停止段时整根轴就不再响应 Pan/Tilt 了——那不是想要的行为。存量资产里存着 Stop 的 38 处会自动重定向到 Off。

### 3.1 Position（定位段）

**定位段给的是相对量，不是绝对角。** 子属性的物理量表示"从当前位置**再**转过多少度"，它被写进一个独立的偏移字段，最终目标角 = **Pan / Tilt 通道给的绝对角 + 这个偏移**。

两者分开存是必须的：写同一格的话，两条通道会按绑定顺序互相覆盖，表现为"推一个另一个就失灵"。分开存之后与绑定顺序无关。

**厂商把定位段的物理量留空时（不少见），这一段按 `Off` 处理**——含义就是"交回给独立的 Pan / Tilt 通道"。不能硬写成 0 度：那会跟 Pan 通道抢同一根轴，表现为推 Pan 时被这条通道拽回原点。

### 3.2 转速从哪来

**优先取灯库里声明的物理量。** GDTF 把 `PanRotate` / `TiltRotate` 的 PhysicalUnit 声明为 AngularSpeed，是真实可用的量纲（实测 Ayrton Mamba 是 ±240 度/秒）。

**没有声明物理量时，按归一化值映射到 ±360 度/秒**——不会因此不转。

**无极旋转不受 Max Speed 限制**——那是"转到某个角度"的最大速度，与持续旋转是两套参数。

角度会被收进 [−180°, 180°)，所以连续转几小时也不会因为浮点精度塌掉。

**静息值不再持续转动**：放进场景、没给 DMX 的灯，图案轮与棱镜是停着的。

## 4. 多头灯

一支灯的每个发射器可以带自己的两根头轴：

| 字段 | 说明 |
| --- | --- |
| Head Axis A (Pan) | 这颗头自己的摇摆轴 |
| Head Axis B (Tilt) | 这颗头自己的俯仰轴 |

字段结构与主轴完全相同（Enabled / Rotation Axis / Pivot Offset / Range / Invert / Max Speed）。

头轴与主轴**共用同一条 PT 速度通道**的减速系数，但各自有独立的行程与限速。

绑定时用 **Emitter Index** 指定这条通道作用在第几个发射器上——这就是多头灯每颗头各转各的做法。

## 5. 排查

### 控台推 Pan，灯不动

按顺序查：

1. 钻机里 **Axis A 的 Enabled** 开着吗；
2. 当前 DMX 模式的绑定里有没有一条 **Axis A Position**，它的 Attribute 是不是通道库里真实存在的属性名；
3. 场景灯具的 `ControlMode` 是 `DMX` 吗；
4. Universe 与起始地址对得上吗。

第 1、2 步在[灯具编辑器](03_FixtureEditor_zh.md)的 **Validation** 页能一次看完；第 3、4 步见 [DMX 灯具基础](../stagecore/03_DMX_Actor_Base_zh.md)。

### 行程不对 / 转过头

看那根轴的 **Range**。它应当是从 GDTF 包内声明导入的值，不是兜底的 ±270。

### 灯头绕错了点转

看那根轴的 **Pivot Offset**。用灯具编辑器 DMX Test 页的 **Rig** 辅助——它在模型上画出每根轴的旋转线、枢轴与行程弧，这是确认枢轴有没有落在机械关节上的唯一可靠办法。

### 是瞬移，不是转过去

那根轴的 **Max Speed** 是 0（不限速）。填一个真实角速度。

### 推了速度杆没变化

速度通道只缩放"转到目标角"的过程。轴的 Max Speed 是 0 时本来就瞬间到位，没有可缩放的速度。

### 无极旋转不转

1. 绑定里有 **Axis A / B Infinite Rotation** 吗；
2. 通道值落在哪一段？前面的定位段本来就不转，要推到正转 / 反转段；
3. 那一段的 **RotationMode** 是 `Infinite` 吗——是 `Position` 或 `Off` 就不会持续转。

没有声明物理量不是原因：那种情况会按 ±360 度/秒兜底，仍然会转。

### 推 Pan 时灯被拽回某个角度

无极旋转通道的定位段物理量被硬填成了 0。定位段留空时应当按 `Off` 处理、把轴交回 Pan / Tilt；填了 0 就变成"再转 0 度"的相对量，与 Pan 抢同一根轴。检查通道库里那一段的物理范围。
