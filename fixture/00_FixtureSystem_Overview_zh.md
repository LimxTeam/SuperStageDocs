# 灯具系统总览

> 适用版本：SuperStage 26H2.6 起

从 26H2.6 开始，一支灯不再是一个蓝图资产，而是一份**灯具定义**。定义可以导入、编辑、升级，场景里所有数据驱动灯具共用同一个 Actor 类，型号由它引用的定义决定。

本文档说明这套体系由哪些资产组成、它们之间是什么关系，以及你在什么场合会打开哪一个。

---

## 1. 三种资产

| 资产 | 回答的问题 | 资产名 |
| --- | --- | --- |
| **灯具定义**（Super Fixture Definition） | 这支灯长什么样、怎么动、从哪出光 | **直接用型号名，不带前缀** |
| **通道库**（Super Fixture Library） | 这支灯的某个 DMX 模式有哪些通道 | `CL_<型号>_<模式名>` |
| **棱镜预设**（Super Prism Preset） | 棱镜把光束分成几份、怎么排 | `SP_<型号>_Prism` |

> 一个型号占一个文件夹，文件夹里那个**与文件夹同名、没有前缀**的资产就是灯具定义。同目录下带前缀的都是它引用的素材：`LTC_` 是浏览器缩略图，`LTA_` 是图案轮图集，`CLA_` 是色盘图集，`SM_` 是模型。

它们的关系：

```text
灯具定义 MegaPointe
 ├── 身份      厂商 / 型号 / 分类 / 缩略图
 ├── 物理      功率 / 重量 / 光通量 / 原生色温 / 灯体尺寸
 ├── 钻机      底座网格 + 轴 A（灯臂）/ 轴 B（灯头）/ 轴 C（自转）
 ├── 发射器    从哪里出光、光束类型、镜片、变焦范围
 ├── 光学      图案轮图集 ×3 / 色盘图集 ×3 / 棱镜预设
 └── DMX 模式
      ├── Mode "Standard" ──> 通道库 CL_MegaPointe_Standard
      │                        └── 绑定：哪条通道驱动哪个能力
      └── Mode "Extended" ──> 通道库 CL_MegaPointe_Extended
                               └── 绑定
```

- 一份定义可以有多个 DMX 模式，每个模式指向一份通道库；
- 一份通道库可以被多份定义共用（同系列不同型号常见）；
- 棱镜预设也可以被多支灯共用。

**发射器是一个列表，不是一个。** 这一点容易忽略：

| | 管什么 |
| --- | --- |
| 发射器的**排布**（Layout） | 把**同一个**发射器复制 N 份——灯条的 1×N、面板的 X×Y、像素分段 |
| 发射器**列表** | 这个型号上本就存在的、**彼此不同**的多个发光体 |

后者是真实存在的：有的灯同时带 BeamMatrix 与 PlateMatrix 两组像素，分段数、网格、挂点、驱动它们的 DMX 属性全都不一样；光束灯再加一圈 Aura 光环也是同理。这些用一个发射器加排布表达不出来。

**默认模式是「第一个通道库有效的模式」**，不是简单的第一个——通道库为空的模式驱动不了任何东西，会被跳过。

> 定义里所有重资产（模型、贴图、棱镜预设）都是**软引用**，通道库是硬引用。这就是资产浏览器能在不加载定义的前提下列出几百个型号的原因——厂商、型号、分类与缩略图路径都以标签形式暴露给资产注册表。

## 2. 灯具定义与通道库的分工

这是最容易混的一点。

| | 灯具定义 | 通道库 |
| --- | --- | --- |
| 描述的是 | 这支灯**是什么**——外形、机械、光学 | 这支灯**怎么被控制**——通道表 |
| 换一个 DMX 模式 | 定义不变 | 换一份通道库 |
| 换一支同厂同系列的灯 | 换一份定义 | 通道库可能可以直接复用 |
| 在哪里编辑 | 灯具编辑器的 Fixture 页 | 通道库编辑器 |

**绑定**住在定义的模式里，不在通道库里。它记的是"通道库里名为 `Pan` 的属性，驱动轴 A 的位置"这类对应关系。所以同一份通道库配到两支机械结构不同的灯上时，各自的绑定可以不同。

## 4. 编译

灯具定义是**源数据**，运行时读的是它的**编译产物**。改完定义需要编译一次，场景里的灯才会跟着变。

编译会做这几件事：把三根轴编成产物、把发射器按排布展开成实例、把绑定展开成运行时操作码、算出通道跨度、跑一遍校验。校验结果在灯具编辑器的 **Validation** 页。

### 4.1 两个编译入口，行为不同

| 入口 | 做什么 |
| --- | --- |
| **灯具编辑器**的 Compile 按钮 | **先按当前通道库重建全部绑定，再编译。**两件事在同一个事务里，撤销一次一起退回 |
| **内容浏览器右键** → Compile（支持多选批量） | **只编译，不重建绑定。**用于改过导入器或编译器之后把整个灯库刷一遍 |

改过通道库之后要用**编辑器里的** Compile——右键批量编译不会重新推导绑定，等于拿旧绑定去编译。

### 4.2 编译结果必须保存

运行时在产物缺失或过期时会**就地重新编译**，所以灯不会不亮。但那份结果**不回存**——每次加载都要重来一遍，永远收敛不了。

**在上面两个入口编译之后，资产被标脏但不会自动保存，要自己存一次**，之后加载才不再重编。

> 插件升级后如果场上灯全不亮，先把灯具定义批量编译一次再保存。26H2.6 已经对"升版后产物过期却判成不用重编"这条路做了处理：产物头部的版本不兼容时直接判为过期，从而触发重编。

### 4.3 复制定义会换新身份

在内容浏览器里复制一份定义资产，副本会**自动分配新的 GUID**——复制出来的是一个新型号。不换的话，MVR 导出与资产浏览器会把原型号与副本归并成同一个型号。

## 5. 一支灯从数据到画面

```text
控台 / DMX 网络
      │  Universe + 起始地址
      ▼
灯具 Actor ──> 当前 DMX 模式的通道库 ──> 按通道号取值
      │
      │  绑定：属性名 → 能力（Op）+ 发射器下标 + 精度
      ▼
能力求值 ──> 轴（Pan/Tilt/自转）
         ├─> 锥形光（光斑、图案、色轮、切割、棱镜）
         ├─> 空中光柱（体积光束 / 纯光束 / Wash / 不画）
         └─> 像素矩阵、效果平面
```

灯具能响应哪些功能，取决于这条链上每一环都齐：通道库里有这条通道、绑定把它接到了某个能力、发射器的光束类型支持这个能力。缺任何一环，控台推得动但画面没反应。排查顺序见 [灯具编辑器](03_FixtureEditor_zh.md) 的 DMX Test 页。

## 6. 与旧版蓝图灯具的关系

26H2.6 之前，一支灯是一个蓝图资产。**蓝图灯具已在本版废弃**，文档不再收录其用法。

- **既有项目请不要就地升级**。灯具资产的结构与命名变动很大，本版不提供旧蓝图灯具到定义资产的类重定向。用旧版蓝图灯的项目请继续使用旧版插件。
- 本版保留的重定向只有 Cutting → Shaper 一组，管的是现役资产里按名字存着的组件类、材质节点、枚举值与蓝图函数。
- 旧文档中以"灯具蓝图"、"通道开关"为中心的说明只适用于旧版插件，本目录已不再提供。
